Build a Wi-Fi smart LED controller with ESP32

Sixty addressable LEDs, controlled from any phone on your network — and ready to hand over to Google Assistant. This is the build from the video, written down properly.

What you’ll build

A WS2812B strip driven by an ESP32 over Wi-Fi: turn it on and off, set any colour from a simple HTTP endpoint, and keep the whole thing inside a safe power budget. The same firmware structure later plugs into SinricPro for “Hey Google” control — that integration is covered in the video.

Wiring

Power math: each WS2812B can draw ~60 mA at full white. Sixty LEDs = 3.6 A worst case. The firmware caps this at 2 A with setMaxPowerInVoltsAndMilliamps(), so a 2 A supply is safe for this build.

The build

01

Wire the level shifter first

The ESP32 speaks 3.3 V; the strip expects 5 V data. It often works without a shifter on the bench and then flickers forever once installed — wire the 74AHCT125 now and never think about it again. Data from GPIO 16 into 1A, output 1Y through the 330 Ω resistor to DIN.

02

Power the strip separately

Strip 5 V and GND go straight to the PSU with the 1000 µF cap across them. Then tie all grounds together — ESP32, shifter, strip, PSU. Ninety percent of “my LEDs show random colours” problems are a missing shared ground.

03

Flash the firmware

Install FastLED from the library manager, paste the full code below, set your Wi-Fi credentials, and upload. The serial monitor prints the board’s IP once connected.

04

Control it from anything

From any device on your network: http://<ip>/on, /off, or /color?r=255&g=90&b=0. That HTTP layer is exactly what the Google Assistant bridge talks to in the video.

Full code

smart-led.ino 
// Smart LED controller — ESP32 + WS2812B
// Techie Heshan — full write-up: techieheshan.com
// Board: ESP32 DevKit V1 | Library: FastLED 3.6+

#include <WiFi.h>
#include <WebServer.h>
#include <FastLED.h>

#define DATA_PIN    16        // through 74AHCT125 level shifter
#define NUM_LEDS    60
#define MAX_MA      2000      // power budget: 5 V x 2 A supply

const char* WIFI_SSID = "YOUR_WIFI";      // EDIT
const char* WIFI_PASS = "YOUR_PASSWORD";  // EDIT

CRGB leds[NUM_LEDS];
WebServer server(80);
CRGB current = CRGB::White;
bool powered = false;

void applyState() {
  fill_solid(leds, NUM_LEDS, powered ? current : CRGB::Black);
  FastLED.show();
}

void handleOn()  { powered = true;  applyState(); server.send(200, "text/plain", "ON");  }
void handleOff() { powered = false; applyState(); server.send(200, "text/plain", "OFF"); }

void handleColor() {
  // /color?r=255&g=120&b=0
  current.r = server.arg("r").toInt();
  current.g = server.arg("g").toInt();
  current.b = server.arg("b").toInt();
  powered = true;
  applyState();
  server.send(200, "text/plain", "OK");
}

void setup() {
  Serial.begin(115200);

  FastLED.addLeds<WS2812B, DATA_PIN, GRB>(leds, NUM_LEDS);
  FastLED.setMaxPowerInVoltsAndMilliamps(5, MAX_MA);
  FastLED.clear(true);

  WiFi.mode(WIFI_STA);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) { delay(300); Serial.print("."); }
  Serial.printf("\nConnected: %s\n", WiFi.localIP().toString().c_str());

  server.on("/on",    handleOn);
  server.on("/off",   handleOff);
  server.on("/color", handleColor);
  server.begin();
}

void loop() {
  server.handleClient();
}

Troubleshooting

First LED works, rest are garbage

Data integrity problem: check the 330 Ω resistor is in line, the shifter is actually a 74AHCT125 (the HC version won’t reliably read 3.3 V), and the data wire is short.

Colours are wrong (red shows green)

Your strip is RGB-ordered, not GRB. Change GRB in addLeds<>() to match — it varies between strip batches.

Strip dims or shifts colour along its length

Voltage drop. Inject 5 V at both ends of the strip for anything over one metre.

ESP32 keeps rebooting when LEDs turn on

Brownout: the strip is pulling the shared rail down. Confirm the strip is on its own PSU and only grounds are shared with the board.
